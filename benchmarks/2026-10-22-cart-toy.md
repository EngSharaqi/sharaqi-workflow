# Benchmark: cart coupon toy task — 2026-10-22

One small task, one run per arm per version. It shows a direction, not a
result. Harness, fixture, hidden tests and edge probe: [cart-toy/](cart-toy/).

## Task

`cart-toy/task.txt`, identical in every arm: in a 20-line `src/cart.js`, clamp
a percent coupon above 100 at 0, add a `fixed` coupon type (cents off, never
below 0), throw on a negative value, add tests, don't commit.

## Setup

- Claude Code 2.1.274, headless `claude -p`, `--model opus --effort medium` in
  every arm. The CLI resolved `opus` to `claude-opus-5`, not Opus 5.5.
- Costs, turns and times are Claude Code's own (`--output-format json`).
- v0.6 round: the installed skills-folder copy, whose global cap hook was
  active in the plain arm too. Two of the skill's commands were blocked by the
  allow-list (reading references through bash, writing a diff file).
- v0.7 round: `cart-toy/run.sh`. The plugin was loaded with `--plugin-dir` in
  **both** arms and the installed copy disabled with `enabledPlugins`. The
  allow-list covers everything the skill uses. A logging hook recorded, on
  each Bash or Agent call, whether the session had a sharaqi run marker:
  every call in the skill arm saw it, no call in the plain arm did, and it
  was gone after the session ended.
- Hidden tests (`cart-toy/hidden/`, 9 tests) and the edge probe
  (`cart-toy/probe.mjs`: missing, text and NaN coupon values must throw or
  give a finite number) were run on each arm's working tree afterwards.

## Limits

- One task, one run per arm per version; the plain arm alone moved $0.22
  between rounds.
- The task is tiny. Delegation and the independent reviewer can't pay for
  themselves on it, so it measures overhead only.
- `claude-opus-5`, not Opus 5.5, on CLI 2.1.274.
- The v0.6 round had blocked commands and an active hook in the plain arm;
  the v0.7 round had neither.
- The v0.7 skill arm spent two of its ten turns listing files before reading
  them. That's left as observed. Tuning the skill against this one task would
  overfit.

## Conclusion

On this small task the plain run is still cheaper and faster: $0.39 and 42 s
against $0.59 and 87 s, 7 turns against 10. v0.7 roughly halves v0.6's cost
($1.49 → $0.59) and turns (19 → 10), and loads 62 % less skill text. It keeps
the one thing the skill added: the edge-input check that stops a NaN total,
which the plain run missed in both rounds. Whether delegation pays on a
medium-sized task is still unmeasured ([TEMPLATE.md](TEMPLATE.md)).
