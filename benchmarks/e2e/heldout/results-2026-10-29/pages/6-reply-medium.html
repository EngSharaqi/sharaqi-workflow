I added `POST /orders` and `GET /orders/:id`, and `npm test` passes: all 12 tests, the 2 existing product tests plus 10 new order tests.

**What changed**
- **`src/store.js`**: the store now keeps orders next to products, and `reset()` clears them too. A new `placeOrder(items)` checks for unknown skus line by line (404), then adds up repeated skus and checks stock in first-seen order (409). It only lowers stock and saves the order once both checks pass, so a failed order leaves stock unchanged. A new `getOrder(id)` looks an order up. Both return copies, so callers can't change what's stored.
- **`src/app.js`**: a JSON body that doesn't parse gets a 400 instead of falling through to the existing 500 handler. All the 400 checks run before the store is called. An empty body, `null`, an array, or an item that isn't an object also gets a 400. `qty` has to be an actual integer, so `"2"` and `1.5` are rejected.
- **`test/orders.test.js`**: covers:
  - a successful order, including merged lines, the total, the new stock seen through `GET /products/:sku`, and fetching the order back
  - order ids being unique
  - ordering exactly the stock that's left
  - every 400 case
  - the 400 → 404 → 409 order
  - the 404 and 409 response bodies
  - repeated lines counting together against stock
  - a failed order leaving stock unchanged

Order ids count up as strings (`"1"`, `"2"`, …), and like the catalogue they're kept in memory only, so they start over when the server restarts. I haven't committed anything.
